# OpsMind 完整使用指南

OpsMind 是面向企业 IT 服务台与运维协同场景的多 Agent 演示系统，覆盖服务咨询、工单分诊、故障诊断、账号访问、权限申请、安全事件、变更发布与人工交接。本文依据当前源码整理启动、配置、API、路由、知识库、记忆、监控、评测与排障方法。

> **系统边界**：当前没有接入真实工单、监控、日志平台、IAM、审批、CI/CD、发布平台或安全处置系统。系统可以整理上下文、检索演示知识、生成诊断计划、检查申请字段和交接摘要，但不能据此宣称已经查询进度、创建工单、恢复服务、授予权限、完成审批、执行发布、回滚或清除威胁。

## 1. 定位与核心能力

- **19 类意图识别**：LLM、Embedding、关键词模式三路融合，并提取 `ticket_id`、`service`、`account`、`date`、`error_code` 五类实体。
- **四类 Agent 协同**：`service_desk`、`incident`、`access`、`escalation`，支持主辅路由、并行处理、统一合成和失败降级。
- **动态 Skills**：按 Agent 类型与消息关键词注入服务台、事件响应、访问权限 SOP，支持热加载。
- **共享 RAG**：ChromaDB 向量检索，结合查询改写、并行召回、去重、重排、缓存、熔断与降级。
- **三级记忆**：Redis 工作记忆、ChromaDB 情景记忆、ChromaDB 用户画像。
- **可观测与可评测**：Agent/工具指标、路由降权、请求级工具轨迹、离线降级链路评测、在线意图与 LLM-as-Judge 评测。

HTTP 主链路为：

```text
POST /chat
  -> 读取工作记忆、相关历史、用户画像和会话摘要
  -> 三路意图识别、紧急度判断、实体提取
  -> 低置信度澄清，或主辅 Agent 路由
  -> 按角色注入 Skills，并由模型决定是否调用白名单工具
  -> 单 Agent 回复，或多 Agent 并行后由 ResponseComposer 合成
  -> 写入 Redis，按需压缩到情景记忆，异步更新用户画像
  -> 返回意图、路由、实体、工具和升级信息，保存进程内工具轨迹
```

`/chat` **不会按意图预先强制检索知识库**。普通 Agent 获得 `search_knowledge_base` 工具后，由模型决定是否调用；只有实际调用时才执行查询改写、召回和重排。

## 2. 环境、配置与启动

### 2.1 环境要求

- Docker 与 Docker Compose。
- 可用的 Anthropic API Key，或兼容 Anthropic 协议的模型服务。
- 首次构建和运行需要下载镜像及 ChromaDB 所需模型资源；离线环境需提前准备镜像和资源。

### 2.2 创建配置文件

在仓库根目录执行。Windows PowerShell：

```powershell
Copy-Item .env.example .env
```

其他 shell 可使用：

```bash
cp .env.example .env
```

至少把 `ANTHROPIC_API_KEY` 的占位值替换为真实密钥，并确认模型名对当前账号可用。不要把 `.env` 或真实密钥提交到版本库。

```env
ANTHROPIC_API_KEY=your_key
ANTHROPIC_MODEL=your-model-name
ANTHROPIC_BASE_URL=https://your-compatible-endpoint.example
```

使用官方 Anthropic 默认地址时，将 `ANTHROPIC_BASE_URL` 留空或删除。生产环境还应修改 Redis 默认密码。

### 2.3 主要配置项

| 配置项 | 作用与默认值 |
|---|---|
| `ANTHROPIC_API_KEY` | 必填；应用初始化时即检查，不能使用占位值 |
| `ANTHROPIC_MODEL` | 模型名；源码缺省为 `claude-3-5-sonnet-20241022`，以 `.env` 为准 |
| `ANTHROPIC_BASE_URL` | 可选兼容协议地址；留空使用官方默认地址 |
| `API_HOST` / `API_PORT` | 直接运行源码时的监听地址，默认 `0.0.0.0:8000` |
| `APP_ENV` / `LOG_LEVEL` | 运行环境与日志级别；`APP_ENV=development` 时直接运行源码会启用 reload |
| `REDIS_PASSWORD` | Compose 为 Redis 和应用拼接认证配置；生产环境必须修改示例密码 |
| `REDIS_URL` | Redis 地址；Compose 会覆盖为容器网络地址 |
| `CHROMA_HOST` / `CHROMA_PORT` | ChromaDB 地址；应用默认 `chromadb:8000` |
| `CHROMA_PERSIST_DIRECTORY` | ChromaDB 服务不可用时的本地持久化目录 |
| `ECHOMIND_SKILLS_DIR` | Skills 根目录；Compose 固定为 `/app/skills` |
| `ECHOMIND_SKILLS_MAX_PROMPT_CHARS` | 单次注入 Skills 的总字符预算，默认 `5000` |
| `MONITOR_INTERVAL` | Monitor 采样间隔秒数，默认 `10` |
| `PROMETHEUS_PORT` | 应用内独立 Prometheus 端口；`0` 表示不单独监听，`/metrics` 仍可用 |
| `ALERT_WEBHOOK_URL` | 可选告警 Webhook，留空不推送 |
| `EVAL_BASELINE_PATH` | 评测基线路径；Compose 为 `/app/data/eval/baseline.json` |
| `ECHOMIND_TOOL_TRACE_MAX` | 当前进程保留的请求轨迹上限，默认 `200` |
| `ECHOMIND_MONITOR_FALLBACK_PENALTY` | 专业 Agent 路由回退阈值，默认 `0.5` |
| `ECHOMIND_DEGRADED_THRESHOLD` | LLM 不可用时降级意图融合阈值，默认 `0.15` |

`ECHOMIND_*` 变量、既有仓库目录名和 Compose 服务/容器命名仅用于部署兼容，产品名称为 **OpsMind**。

### 2.4 启动完整服务

```bash
docker compose up -d --build
docker compose ps
docker compose logs -f echomind
```

主要入口：

| 服务 | 地址 | 说明 |
|---|---|---|
| OpsMind API | `http://localhost:8000` | 直连应用，评测也建议走此端口 |
| Swagger | `http://localhost:8000/docs` | 查看并调试当前接口 |
| Nginx | `http://localhost` | 反向代理入口 |
| ChromaDB | `http://localhost:8001` | 宿主机访问端口，容器内部仍为 `8000` |
| Prometheus | `http://localhost:9090` | 监控页面 |

健康检查：

```bash
curl.exe http://localhost:8000/health
```

`/health` 返回 200 只表示应用已初始化，不代表模型调用、检索或评测已经成功。应用容器的健康检查还依赖 Redis 与 ChromaDB 容器健康状态。

### 2.5 交互式 CLI

```bash
docker compose run --rm echomind python api/main.py --cli
```

输入 `quit`、`exit`、`退出` 或空行结束。CLI 支持意图识别、Agent 路由、Skills 和 Redis/ChromaDB 会话记忆，但不会初始化 HTTP 模式下的共享 RAG 工具、Monitor、工具轨迹查询或画像后台更新。验证 RAG、监控和画像时应使用 HTTP `/chat`。

修改 Python 源码后，先重建镜像再运行：

```bash
docker compose build echomind
```

Compose 挂载了 `skills/`、`data/` 和 `logs/`，不是 Python 源码热挂载。Skill 修改可在 HTTP 服务中热加载，CLI 则需重新启动。

## 3. API 与对话示例

### 3.1 接口总览

| 方法 | 路径 | 参数 | 用途 |
|---|---|---|---|
| `GET` | `/health` | 无 | 服务状态和各 Agent 实例统计 |
| `POST` | `/chat` | JSON Body | 主对话链路 |
| `POST` | `/search` | Query：`query`、`top_k=5` | 查询改写、召回、去重和重排 |
| `POST` | `/knowledge/add` | JSON Body：`documents` | 批量导入文档 |
| `POST` | `/knowledge/upload` | Multipart：`file` | 上传文档，最大 10 MB |
| `GET` | `/knowledge/stats` | 无 | 知识库片段总数 |
| `GET` | `/skills` | 无 | Skills 摘要和解析错误 |
| `POST` | `/skills/reload` | 无 | 重新扫描 Skills |
| `GET` | `/monitor` | 无 | Agent、工具、告警和建议 |
| `GET` | `/metrics` | 无 | Prometheus 指标文本 |
| `GET` | `/trace/tools` | Query：`limit=20` | 最近请求的工具轨迹 |
| `GET` | `/trace/tool/{request_id}` | 路径参数 | 单次请求的工具轨迹 |
| `POST` | `/eval/run` | 可选 JSON Body | 在线意图与对话质量评测 |
| `GET` | `/docs` | 浏览器 | Swagger UI |

### 3.2 `/chat` 请求与响应

请求字段：

| 字段 | 必填 | 说明 |
|---|---|---|
| `message` | 是 | 当前用户消息 |
| `user_id` | 否 | 默认 `anonymous`，用于记忆与画像隔离 |
| `conv_id` | 否 | 不传则生成 UUID；多轮对话应保持不变 |

PowerShell 示例：

```powershell
$body = @{
  message = "ERP 系统持续返回 500，今天开始影响财务部，请协助排查"
  user_id = "demo_user"
  conv_id = "erp_incident_demo"
} | ConvertTo-Json

$result = Invoke-RestMethod `
  -Uri "http://localhost:8000/chat" `
  -Method Post `
  -ContentType "application/json; charset=utf-8" `
  -Body ([System.Text.Encoding]::UTF8.GetBytes($body))

$result | ConvertTo-Json -Depth 8
```

响应字段：

| 字段 | 含义 |
|---|---|
| `conv_id` / `request_id` | 会话 ID / 本轮请求 ID，后者用于轨迹查询 |
| `response` | 最终用户回复；多 Agent 时可能是 Composer 合成结果 |
| `intent` / `intent_group` | 细粒度意图 / 归一化意图组 |
| `agent_type` | 最终主返回 Agent |
| `agent_types` | 实际参与并成功返回的 Agent 列表；特定降级路径可能只含实际执行者 |
| `primary_agent` / `supporting_agents` | 主处理 Agent / 辅助 Agent |
| `tools_used` | 成功执行并返回的工具名摘要，不含每个参数的完整细节 |
| `routing_reason` / `routing_confidence` | 路由原因、领域分数 / 主 Agent 路由分数 |
| `escalated` | 本轮是否带有升级标记，不代表已通知外部人员或创建外部记录 |
| `latency_ms` | 本轮编排耗时 |
| `knowledge_used` | 是否成功调用过 `search_knowledge_base`，不代表检索一定有有效内容 |
| `entities` | 五类规则实体，每类均为字符串数组 |
| `intent_confidence` / `intent_source_scores` | 融合意图置信度 / LLM、Embedding、Pattern 等来源分数 |
| `intent_degraded` | 是否走了 LLM 不可用后的降级意图链路；为 `true` 时不要把分数当作正常在线链路结果 |

`intent_confidence` 与 `routing_confidence` 不是同一指标：前者描述意图融合结果，后者描述主 Agent 的领域路由分数。

### 3.3 多轮对话

保持 `user_id` 与 `conv_id` 不变即可：

```powershell
$body = @{
  message = "故障已持续半小时，影响整个上海办公室，请整理升级值班工程师所需的摘要"
  user_id = "demo_user"
  conv_id = "erp_incident_demo"
} | ConvertTo-Json

Invoke-RestMethod `
  -Uri "http://localhost:8000/chat" `
  -Method Post `
  -ContentType "application/json; charset=utf-8" `
  -Body ([System.Text.Encoding]::UTF8.GetBytes($body))
```

系统会读取同会话最近消息和摘要，并检索同一用户的相关历史与画像。记忆存在不代表外部业务状态已被核实。

### 3.4 典型场景输入

| 场景 | 示例消息 | 观察点 |
|---|---|---|
| 服务与工单咨询 | `ERP 服务现在正常吗？另外请查询 INC-2026 的处理进度` | 服务台分诊；无实时监控或工单接入时不能给出实际状态 |
| 应用故障 | `ERP 系统持续返回 500，请给出低风险排查步骤` | `incident`、错误码实体、诊断计划 |
| 性能与网络 | `VPN 连接频繁超时，上海办公室多人受影响` | 影响范围、开始时间、网络与依赖排查 |
| 账号访问 | `账号 zhangsan 登录 ERP 一直报 401` | `access`、账号/服务/错误码实体，不索取秘密凭据 |
| 权限申请 | `为账号 zhangsan 申请 ERP 测试环境只读权限，期限一周，用于数据核验` | 最小权限字段检查与申请摘要，不直接授权 |
| 安全事件 | `账号 zhangsan 出现异常登录，疑似被盗，需紧急升级` | 安全处置边界和人工交接，不声称已封禁或清除威胁 |
| 变更发布 | `申请 ERP 系统生产发布窗口，并核对验证与回滚方案` | 变更材料、风险、窗口与回滚，不执行发布 |

实际意图和路由由当次模型、规则、上下文和监控状态决定，应以响应字段为准，不要把示例输入理解为固定输出承诺。

## 4. 19 类意图、分组与实体

### 4.1 意图清单

下表的“通常主路由”不考虑紧急度覆盖、复合协作、监控回退和执行失败降级。

| 意图值 | `intent_group` | 含义 | 通常主路由 |
|---|---|---|---|
| `query` | `query` | 通用服务与流程咨询 | `service_desk` |
| `service_status` | `query` | 服务运行状态咨询 | `service_desk` |
| `ticket_status` | `query` | 工单进度与分派咨询 | `service_desk` |
| `incident` | `incident` | 通用系统故障 | `incident` |
| `service_outage` | `incident` | 服务中断或大面积不可用 | `incident` |
| `performance_issue` | `incident` | 响应慢、延迟高、超时 | `incident` |
| `application_error` | `incident` | 应用报错、崩溃、错误码 | `incident` |
| `access` | `access` | 通用账号与权限问题 | `access` |
| `account_access` | `access` | 登录、认证、账号恢复 | `access` |
| `permission_request` | `access` | 权限申请与变更 | `access` |
| `security_incident` | `access` | 异常登录、账号盗用、恶意软件等 | `access` |
| `request` | `request` | 通用服务请求 | `service_desk` |
| `change_request` | `request` | 配置变更、发布窗口、规则调整 | `service_desk` |
| `escalation` | `escalation` | 升级二线或值班角色 | `escalation` |
| `human_handoff` | `escalation` | 明确人工处理诉求 | `escalation` |
| `complaint` | `complaint` | 服务投诉与不满 | `service_desk` |
| `greeting` | `greeting` | 问候 | `service_desk` |
| `feedback` | `feedback` | 正面反馈 | `service_desk` |
| `other` | `other` | 无法可靠归类 | 澄清或 `service_desk` |

### 4.2 融合、降级与澄清

正常链路的基础权重为：

```text
LLM 0.70 + Embedding 0.20 + Pattern 0.10
```

系统先按 `intent_group` 合并领域分数，再在获胜领域内选择细粒度意图。Pattern 可以把同组粗意图细化为具体意图，但不能跨组覆盖。正常路径组分数低于默认阈值 `0.5` 时返回 `other`。

LLM 不可用时，系统只在可用的 Embedding/Pattern 来源间重新归一化权重，并使用独立降级阈值，默认 `0.15`。此时响应中的 `intent_degraded=true`，应结合日志修复模型链路，而不是把降级结果视为正常在线识别质量。

当意图为 `other`、置信度低于 `0.5` 且消息长度大于 2 个字符时，Orchestrator 先追问服务、故障、账号权限或变更方向，不调用普通 Agent。

### 4.3 实体提取

| 实体 | 示例 | 说明 |
|---|---|---|
| `ticket_id` | `INC-2026`、`REQ-1001`、`CHG-2026`、`PRB-008` | 支持标准前缀及“工单号”等表达 |
| `service` | `ERP`、`VPN` | 从“某服务/系统/应用/平台”表达中提取 |
| `account` | `zhangsan`、`user@example.com` | 仅账号标识，不应包含密码或验证码 |
| `date` | `今天`、`明天`、`下周`、`2026-11-01` | 规则日期表达 |
| `error_code` | `401`、`403`、`500` | 提取 4xx/5xx 数字错误码 |

实体由本地规则提取，空数组表示未识别，不代表对应信息在企业系统中不存在。

## 5. 四类 Agent、路由与工具

### 5.1 角色与白名单

所有普通角色可共享 `search_knowledge_base`，并叠加各自工具：

| Agent | 职责 | 角色工具 |
|---|---|---|
| `service_desk` | 服务目录、工单分诊、请求澄清、变更材料整理 | `inspect_request_context`、`suggest_required_fields` |
| `incident` | 服务中断、性能下降、应用报错与诊断计划 | `lookup_error_code`、`build_diagnostic_plan` |
| `access` | 登录认证、最小权限检查、权限申请与安全协同 | `check_access_fields`、`build_access_request_summary` |
| `escalation` | 重大事件和明确人工诉求的结构化交接 | 定义了 `create_handoff_summary` 白名单；当前直接交接实现不调用 LLM 或工具 |

工具都是确定性的上下文分析或摘要工具：

- `lookup_error_code` 只解释常见错误和排查方向，返回中明确未检查服务端日志。
- `build_diagnostic_plan` 只生成低风险排障顺序，不修改配置。
- `check_access_fields` 只检查字段，不连接 IAM 或审批系统。
- `build_access_request_summary` 只生成待审批摘要，`submitted=false`。
- `create_handoff_summary` 只整理交接信息，不创建外部记录。

### 5.2 路由优先级

1. **紧急度覆盖**：`CRITICAL` 直接进入 `escalation`。`service_outage`、`security_incident` 默认具有该紧急度，消息中的紧急关键词也可能触发。
2. **明确升级**：`escalation`、`human_handoff` 进入 `escalation`。
3. **领域打分**：按意图、领域关键词和实体计算 `service_desk`、`incident`、`access` 分数，最高分成为主 Agent。
4. **复合协作**：同时命中故障和账号访问领域时，另一个专业 Agent 可进入 `supporting_agents`；分数接近的专业领域也可能成为辅助 Agent。
5. **性能选择**：同一类型存在多个实例时，按成功率、延迟和 Monitor 降权形成的 `routing_score` 选实例。
6. **回退与失败降级**：专业类型全部达到 Monitor 降权阈值时回退到 `service_desk`；专业 Agent 执行失败时也尝试由 `service_desk` 接管。

`escalation` 节点当前直接生成本地交接文字。`escalated=true` 是本轮处理标记，不是外部通知或处置回执。

### 5.3 复合问题示例

```text
ERP 登录持续报 401，同时 VPN 连接超时，账号是 zhangsan
```

这句话同时包含账号访问和服务故障信号。Orchestrator 可能选择 `incident` 与 `access` 中的一个作为主 Agent、另一个作为辅助 Agent，并行执行后由 ResponseComposer 去重、协调冲突并保留排查与升级边界。应检查：

- `primary_agent`、`supporting_agents`、`agent_types`
- `routing_reason` 中的各领域分数
- `tools_used` 和请求级 `tool_calls`

Composer 失败时使用确定性的“主回复 + 补充说明”合并，不应把任何合成文本当作真实后台执行证据。

## 6. Skills 动态业务规范

Skills 约束“如何处理、需要哪些字段、何时升级、哪些动作不能做”；RAG 知识库提供“制度与 SOP 中写了什么”。两者不能互相替代。

当前目录与角色映射：

| 目录 | 当前规范 | `agents` 值 |
|---|---|---|
| `skills/general_customer_service/` | IT 服务台分诊规范 | `service_desk` |
| `skills/technical_support/` | IT 事件响应与故障诊断规范 | `incident` |
| `skills/access_support/` | 账号访问与权限安全规范 | `access` |

这些目录名仅为兼容保留，实际路由和 Skill 匹配使用表中的新 Agent 值。

Markdown 示例：

```markdown
---
name: VPN 事件排查规范
description: VPN 超时、影响范围确认与升级边界
keywords: VPN,超时,无法连接,办公室
agents: incident
enabled: true
---

# VPN 事件排查规范

先确认受影响服务、开始时间、范围和最近变更，再给出可验证的低风险步骤。
```

匹配规则：

- `agents` 为空表示适用于所有 Agent，否则仅匹配指定角色。
- `keywords` 为空表示全局注入，否则用户消息至少命中一个关键词。
- `enabled=false` 禁用。
- 单个 Skill prompt 块有长度限制，所有命中 Skills 还受 `ECHOMIND_SKILLS_MAX_PROMPT_CHARS` 总预算约束。
- 系统角色与安全边界优先于 Skill 文本。

查看和热加载：

```bash
curl.exe http://localhost:8000/skills
curl.exe -X POST http://localhost:8000/skills/reload
```

`/skills` 返回 `root_dir`、`count`、`skills`、`errors`。若未生效，先检查该接口中的路径、角色、关键词、启用状态和解析错误。

## 7. RAG 知识库

### 7.1 存储与默认内容

知识库使用 ChromaDB collection `knowledge_base`，与记忆 collection 分离。首次启动时若 collection 为空，会导入六类 OpsMind 演示制度/SOP：服务状态与工单、故障诊断与事件升级、账号访问、权限申请、安全事件响应、变更发布与回滚。这些文档明确是演示材料，不是企业实时数据。

文档按句号和换行切成约 500 字片段；单个超长句子不会被强制截断。片段 ID 由标题、序号和内容前 50 字生成，写入使用 `upsert`：

- 相同文档重复导入具有幂等性。
- `added_chunks` 是本次处理的片段数，不是净新增数量。
- 修改内容导致 ID 改变时，旧片段不会自动删除。
- 导入后不会主动清空 300 秒检索缓存，相同查询短时间内可能仍返回缓存结果。

### 7.2 批量导入

```powershell
$body = @{
  documents = @(
    @{
      title = "VPN 故障演示 SOP"
      content = "VPN 连接超时时，记录开始时间、影响区域、客户端版本和最近网络变更。先验证网络、DNS、代理与证书，不得声称已经查看网关监控。"
    },
    @{
      title = "ERP 权限申请演示规范"
      content = "申请 ERP 权限需提供账号标识、目标环境、资源范围、权限级别、业务理由和有效期。生产高权限需进入真实审批流程。"
    }
  )
} | ConvertTo-Json -Depth 6

Invoke-RestMethod `
  -Uri "http://localhost:8000/knowledge/add" `
  -Method Post `
  -ContentType "application/json; charset=utf-8" `
  -Body ([System.Text.Encoding]::UTF8.GetBytes($body))
```

返回 `added_chunks` 和 `total_chunks`。查看总数：

```bash
curl.exe http://localhost:8000/knowledge/stats
```

### 7.3 上传文件

```bash
curl.exe -X POST http://localhost:8000/knowledge/upload -F "file=@data/demo_docs/sample_knowledge.json"
```

- `.json` 必须是 `[{"title":"...","content":"..."}]` 数组。
- `.txt`、`.md` 按 UTF-8 文本整篇导入，文件名去后缀作为标题。
- 当前代码对其他后缀也按文本处理，并不做严格类型白名单。
- 单文件最大 10 MB；上传前仍应自行审查敏感信息。

### 7.4 检索链路

PowerShell 检索示例：

```powershell
$query = [Uri]::EscapeDataString("VPN 连接超时如何排查")
Invoke-RestMethod -Method Post `
  -Uri "http://localhost:8000/search?query=$query&top_k=3"
```

返回结构为 `query`、`results`、`reranked`；每个结果包含 `title`、`content`、`score`、`chunk`。

```text
原始查询
  -> LLM 尝试生成多个改写查询
  -> 并行调用 knowledge_search，单个子查询可命中 300 秒缓存
  -> ChromaDB 向量召回、合并与内容去重
  -> 结果超过 top_k 时尝试 LLM 重排，失败则保留召回顺序
  -> 返回 Top-K；Agent 调用场景再把结果交回模型
```

知识库异常时，MCP fallback 可能返回带 `fallback=true` 的降级说明。`/chat` 的 `knowledge_used=true` 仅表示工具被成功调用，不能单独证明检索到了有效制度内容；当前轨迹也不保存工具结果正文和 fallback 标记。

## 8. 三级记忆

| 层级 | 存储位置 | 内容与读取方式 |
|---|---|---|
| 工作记忆 | Redis `wm:{user_id}:{conv_id}` | 当前会话最近消息，LPUSH 写入，读取时恢复时间顺序，TTL 24 小时 |
| 会话摘要 | Redis `summary:{user_id}:{conv_id}` | 工作记忆压缩后的摘要，TTL 24 小时，随上下文一起提供 |
| 情景记忆 | ChromaDB `episodic` | 压缩摘要及元数据，按用户和会话语义检索，可回退到同一用户跨会话历史 |
| 用户画像 | ChromaDB `user_profile` | 偏好、常用服务、账号与资源、问题类型，HTTP `/chat` 后异步提炼 |

“三级记忆”指工作记忆、情景记忆和用户画像；Redis 会话摘要是对工作记忆压缩流程的补充。

### 8.1 压缩规则

```text
WORKING_MAX = 20   # 单次从 Redis 读取的上限
COMPRESS_AT = 15   # 达到 15 条消息即触发压缩
保留最近 5 条消息
```

一次 `/chat` 通常写入用户和助手两条消息，因此“15 条”不是“15 轮”。从空会话开始，第 8 轮写入用户消息时就可能触发压缩。

```text
较旧消息 -> LLM 摘要 -> Redis summary
较旧消息原文预览 + 摘要 -> ChromaDB episodic
最近 5 条 -> 继续保留在 Redis wm 列表
```

摘要生成失败时会保留保守的失败说明；画像更新依赖 LLM，且为异步任务，失败不会阻塞当前回复。CLI 不执行画像后台更新。

### 8.2 排查入口

Redis 容器为 `echomind-redis`。使用当前实际密码进入客户端：

```bash
docker exec -it echomind-redis redis-cli -a "替换为当前Redis密码"
```

常用只读命令：

```redis
LRANGE wm:demo_user:erp_incident_demo 0 -1
GET summary:demo_user:erp_incident_demo
TTL wm:demo_user:erp_incident_demo
```

ChromaDB 三个 collection 为 `knowledge_base`、`episodic`、`user_profile`。宿主机服务端口为 `8001`，应用容器内访问地址为 `chromadb:8000`。不要把宿主机的 `localhost:8001` 配成应用容器内部地址。

## 9. 监控、工具轨迹与降级

### 9.1 运行监控

```bash
curl.exe http://localhost:8000/monitor
curl.exe http://localhost:8000/metrics
```

`/monitor` 主要字段：

| 字段 | 内容 |
|---|---|
| `agent_stats` | 调用次数、成功率、平均延迟、`monitor_penalty`、`routing_score` 等 |
| `tool_stats` | 工具调用次数、成功率、平均延迟、连续失败和熔断状态 |
| `active_alerts` | 当前告警 |
| `suggestions` | 基于运行指标的建议 |

Monitor 默认每 10 秒采样。成功率或延迟超阈值时会计算降权；专业类型所有实例都达到回退阈值时，新请求可回到 `service_desk`。通过 `/chat` 的 `routing_reason` 是否含 `monitor_fallback=[...]` 判断是否实际发生回退。告警、降权、路由回退和模型质量评测是不同概念。

Prometheus 页面位于 `http://localhost:9090`；`/metrics` 只暴露指标文本，不代表存在真实基础设施监控接入。

### 9.2 请求级工具轨迹

先保存 `/chat` 返回的 `request_id`，再查询：

```bash
curl.exe "http://localhost:8000/trace/tools?limit=20"
curl.exe "http://localhost:8000/trace/tool/替换为实际request_id"
```

单次查询返回 `request_id`、`found`、`trace`。轨迹包含：

- `intent`、`primary_agent`、`supporting_agents`
- `tools_used`、`escalated`、`latency_ms`
- `tool_calls` 中的 `agent_type`、`tool_name`、`tool_use_id`、`input`
- `success`、`result_success`、`latency_ms`、`cached`、`reranked`、`error`

没有工具调用的请求也会留下空 `tool_calls` 记录。轨迹只保存在当前应用进程内存中，默认最多 200 条；进程重启、多实例切换或超过容量后可能查不到。`result_success` 也不能替代对检索内容和外部执行回执的核验。

## 10. 离线与在线评测

### 10.1 离线 Harness：只测确定性及降级链路

在仓库根目录执行：

```bash
python _offline_harness/run.py --cases data/eval/intent_cases.json
```

自定义报告路径：

```bash
python _offline_harness/run.py --cases data/eval/intent_cases.json --json-out _offline_harness/reports/offline_metrics.json --md-out _offline_harness/reports/offline_metrics.md
```

降级阈值标定：

```bash
python _offline_harness/calibrate_threshold.py
```

Harness 通过依赖桩强制 LLM 调用失败，运行项目真实的 Pattern、本地向量、降级融合、实体、紧急度、路由、澄清、熔断、缓存、fallback 和 Skills 预算逻辑。退出码 0 只表示 Harness 完成，不表示模型质量好。

**离线结果不能代表在线质量**：它没有测量正常 LLM 语义识别、查询改写、重排、LLM-as-Judge、多 Agent Composer，也不覆盖真实 RAG/Redis/ChromaDB 服务、在线延迟、Token 成本、并发和限流。`ECHOMIND_DEGRADED_THRESHOLD` 的离线标定同样只适用于 LLM 不可用时的降级分布。

### 10.2 在线 API 评测

`POST /eval/run` 会真实调用模型：

1. 意图识别 Accuracy、Macro-F1 和逐类 Precision/Recall/F1/support。
2. Orchestrator 生成单轮或多轮回复。
3. LLM-as-Judge 按 `relevance`、`accuracy`、`completeness`、`helpfulness` 评分。
4. 与进程内上一次报告或已加载基线比较，相对下降超过 5% 时记录回归。
5. 返回建议并保存当前报告为基线。

运行内置用例：

```bash
curl.exe -X POST http://localhost:8000/eval/run
```

自定义用例的 PowerShell 示例：

```powershell
$body = @{
  intent_cases = @(
    @{ message = "ERP 页面持续返回 500"; expected_intent = "application_error" },
    @{ message = "申请 VPN 的临时访问权限"; expected_intent = "permission_request" }
  )
  dialog_cases = @(
    @{ question = "账号 zhangsan 登录 ERP 一直报 401，应收集哪些信息？" },
    @{ turns = @(
      "VPN 连不上，请先帮我分诊",
      "已经持续半小时，影响整个上海办公室",
      "请整理升级值班工程师的摘要"
    ) }
  )
} | ConvertTo-Json -Depth 8

Invoke-RestMethod `
  -Uri "http://localhost:8000/eval/run" `
  -Method Post `
  -ContentType "application/json; charset=utf-8" `
  -Body ([System.Text.Encoding]::UTF8.GetBytes($body)) `
  -TimeoutSec 1800
```

请求模型支持：

- `intent_cases[]`：`message`、`expected_intent`，可选 `context`。
- `dialog_cases[]`：单轮 `question` 或多轮 `turns`，可选 `user_id`、`conv_id`。
- 某个数组缺省时使用对应内置用例；显式传空数组表示该部分不执行。

响应包含 `pass_rate`、`total`、`passed`、`avg_scores`、`degraded_count`、`degraded_rate`、`regressions`、`recommendations`、`results`。意图和对话综合分的通过阈值均为 `0.75`。

Judge 两次尝试仍无法取得合法评分时，会使用 0.5 兜底并标记测量失效。只要 `degraded_rate > 0`，就不能把 `pass_rate` 和受影响评分直接作为质量结论，应先修复 Judge 调用或解析链路。

评测对话直接调用 Orchestrator 并维护本地短历史，不经过 `/chat` 的 Redis 记忆读写和画像更新，但可能使用已注册的 Agent 工具。

### 10.3 一键在线验证脚本

PowerShell：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\run_online_eval.ps1
```

脚本默认执行健康检查、Skills、知识统计、按需导入演示知识、两轮 `/chat`、Monitor 和 `data/eval` 数据集评测。常用参数：

```powershell
# 只做冒烟，不跑模型评测
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\run_online_eval.ps1 -SkipEval

# 只跑数据集中的意图用例
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\run_online_eval.ps1 -EvalSet intent-only

# 使用源码内置用例

```

## 12. 故障排查

### 12.1 服务未就绪或 `/health` 返回 503

```bash
docker compose ps
docker compose logs --tail=120 echomind
docker compose logs --tail=80 redis
docker compose logs --tail=80 chromadb
```

检查 `.env` 是否存在、API Key 是否仍为占位值、模型名是否可用，以及 Redis/ChromaDB 是否健康。应用启动前会读取模型配置，因此缺少 API Key 不是可忽略的聊天时错误。

### 12.2 `/chat` 失败或 `intent_degraded=true`

- 核对 `ANTHROPIC_API_KEY`、`ANTHROPIC_MODEL`、`ANTHROPIC_BASE_URL` 是否与服务商一致。
- 查看应用日志中的鉴权、连接、配额或模型错误。
- `intent_degraded=true` 表示意图识别进入 LLM 不可用后的降级路径；普通回复也可能因模型异常而失败或回退。
- 不要把 `/health=ok` 当作模型链路正常的证据，应实际调用一条保守的 `/chat` 示例验证。

### 12.3 ChromaDB 连接或数据异常

```bash
docker compose ps chromadb
docker compose logs --tail=100 chromadb
curl.exe http://localhost:8001/api/v1/heartbeat
```

应用连接独立服务失败时会尝试 `CHROMA_PERSIST_DIRECTORY` 本地持久化模式。此时数据可能落在另一套存储中，应先从日志确认实际模式，不要假设两套数据自动同步。容器内地址使用 `chromadb:8000`，宿主机直连才使用 `localhost:8001`。

### 12.4 Redis 认证失败或记忆丢失

- 确认 `REDIS_PASSWORD` 与当前容器配置一致；Compose 会覆盖应用的 `REDIS_URL`。
- 检查 `user_id`、`conv_id` 是否完全一致，以及工作记忆 24 小时 TTL 是否已过期。
- 压缩后 `wm` 只保留最近 5 条，较早内容应查看 `summary` 和 `episodic`。
- 情景记忆只有达到 15 条消息并执行压缩后才出现；画像还需等待 HTTP 请求后的异步 LLM 更新。

### 12.5 `/search` 无结果或结果未更新

1. 调用 `/knowledge/stats`，确认片段数不是 0。
2. 导入当前运维演示文档，再用明确的服务名、错误码或流程关键词检索。
3. 查看日志，区分真实召回、重排失败和知识库 fallback。
4. 导入新内容后注意 300 秒缓存；更换查询或等待缓存过期再核对。
5. `reranked=false` 只表示未执行或未完成重排，不等于没有召回结果。

### 12.6 Skills 未命中

- 查看 `/skills` 的 `errors`、`path`、`agents`、`keywords`、`enabled`。
- 确认角色值为 `service_desk`、`incident`、`access` 或留空，不要用目录名代替 Agent 值。
- 确认消息确实命中关键词，且总 prompt 预算尚未耗尽。
- 修改后调用 `/skills/reload`，再发一条能命中关键词的新消息。

### 12.7 工具轨迹查不到

确认 `request_id` 来自当前应用进程，且未重启、未切换到其他实例、未超过轨迹容量。无工具调用时 `found=true` 但 `tool_calls=[]` 是正常情况；`knowledge_used=false` 也只表示没有成功完成该工具调用。

### 12.8 在线评测超时或评分异常

- 直连 `8000`，不要通过当前 Nginx 跑完整评测。
- 先用 `-SkipEval` 完成冒烟，再选择 `intent-only` 缩小范围。
- 检查模型连接、超时、额度和应用日志。
- 查看 `degraded_count`、`degraded_rate` 与每条结果的 `judge_error`；测量失效不能直接解释为回复质量下降。
- 确认基线来自同一 OpsMind 场景和可比数据版本，不引用历史异场景数字。

## 13. 安全边界与上线前要求

- **不虚构执行**：没有真实工具回执时，只能提供查询路径、诊断建议、材料检查或交接摘要，不能声称外部动作已完成。
- **不收集秘密凭据**：不要发送密码、短信验证码、MFA 密钥、完整 Token、API Key、私钥或未脱敏敏感日志。排障只需账号标识、时间点、错误信息和必要的脱敏上下文。
- **最小权限与人工审批**：权限申请必须明确资源范围、级别、理由和期限；生产高权限、敏感数据访问和长期权限需要真实授权流程。
- **安全事件优先升级**：异常登录、账号盗用、钓鱼、恶意软件和数据泄露迹象，应通过企业可信渠道报告并由授权人员处置；不要点击可疑链接、转发恶意附件或公开敏感证据。
- **生产变更需授权**：发布、回滚、配置修改、流量切换和数据修复必须有影响评估、验证方法、回滚方案和真实审批，不由演示 Agent 直接执行。
- **知识内容需治理**：上传前审查制度来源、有效期和敏感信息。检索片段是参考资料，不是实时状态或执行授权。
- **接口暴露需加固**：当前示例未实现业务身份认证和细粒度接口授权，CORS 配置允许任意来源。不要直接暴露到公网；生产使用前应增加认证、授权、TLS、限流、审计、网络隔离、密钥管理和数据保留策略。
- **评测结果需可审计**：保留真实原始报告、数据版本和配置，区分正常在线、意图降级、Judge 测量失效以及离线降级指标，不把不同口径混为质量结论。
